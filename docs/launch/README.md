# Launch drafts

Copy, edit, post. Nothing here is posted automatically, and nothing here should be posted by
anyone but the author.

## Ground rules

These are not decoration. Breaking them can get a Marketplace publisher removed, and it is the one
kind of damage that cannot be undone by shipping a better version.

- **No fake reviews, no second accounts, no vote rings, no asking friends to five-star it.** Ask
  real users for honest reviews; accept the ones you get.
- **Disclose that you wrote it.** Every venue below expects it, and being caught not saying it is
  worse than any upvote is worth.
- **Read each community's self-promotion rules before posting.** They differ, they change, and
  "I didn't know" is not a defence anyone accepts.
- **Post where the tool is genuinely useful.** A Mermaid diff tool is on-topic in a diagrams-as-code
  discussion and off-topic in a general programming feed.

## Order worth doing them in

1. **mermaid-js Discussions** — smallest, most on-target, least risk. Good place to find the first
   real bug reports before a wider audience arrives.
2. **awesome-list PRs** — slow-burn, permanent, no timing pressure.
3. **dev.to article** — the asset the rest links to. Worth writing before the posts that reference it.
4. **Show HN** — one shot per project, effectively. Do it once the listing has the GIF and the
   article exists to link.
5. **r/vscode** and social — after the above, so the traffic lands somewhere finished.
